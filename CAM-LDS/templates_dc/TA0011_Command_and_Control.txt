======================================================================
  MITRE ATT&CK — TACTIC: TA0011
======================================================================
  ID         : TA0011
  NAME       : Command and Control

  OBJECTIVE  : The adversary is trying to communicate with compromised systems to control them.

----------------------------------------------------------------------
  TECHNIQUES USE
----------------------------------------------------------------------

  Command and Control consists of techniques that adversaries may
  use to communicate with systems under their control within a
  victim network. Adversaries commonly attempt to mimic normal,
  expected traffic to avoid detection. There are many ways an
  adversary can establish command and control with various levels of
  stealth depending on the victim’s network structure and defenses.

----------------------------------------------------------------------
  LINUX DETECTION STRATEGIES
----------------------------------------------------------------------

    Detects suspicious curl, wget, or custom socket traffic that
    leverages DNS, HTTPS, or IRC-style protocols with unbalanced
    traffic or beacon-like intervals.

    Detection of file write-access to USB-mount directories (e.g.,
    /media/, /run/media/) followed by same-file access or execution
    on another host.

    Execve: Execution of curl or wget writing files to /tmp/*
    followed by chmod or execution.

    Custom scripts or processes encode outbound traffic using gzip,
    Base64, or hex prior to exfiltration via curl, wget, or custom
    sockets. Encoding typically occurs before or during outbound
    connections from non-network daemons.

    Identifies custom or previously unseen userland processes
    initiating high-volume HTTP connections with low response
    volume.

    Query to suspicious domain with high entropy or low reputation.

    Socket/connect with TLS context by unexpected process.

    Creation of outbound connections on alternate ports or using
    covert transport (e.g., ICMP, DNS) from non-network-intensive
    processes, following known disruption or blocked traffic.

    Execve: Execution of commands modifying iptables/nftables to
    block selective IPs.

    Shell-based tools (curl, wget, scp) initiate connections to
    external domains followed by creation of executable files on
    disk.

    Shell script or binary initiates curl/wget request to staging
    domain, writes output to disk or memory, and shortly afterward
    launches another process that establishes new outbound
    connection to a different IP or hostname.

    ICMP or raw socket traffic generated by user-mode processes like
    bash, Python, or nc, typically using `ping`, `hping3`, or
    crafted packets via libpcap or scapy.

    Unusual daemons or user processes binding/listening on ports
    outside of standard ranges, or initiating client connections
    using mismatched protocol/port pairings.

    Socket/connect calls showing SSH processes forwarding arbitrary
    ports.

    User-space tools (e.g., `socat`, `ncat`, `iptables`, `ssh`) used
    in non-standard ways to establish reverse shells,
    port-forwarding, or inter-host connections. Often chained with
    uncommon outbound destinations or SSH tunnels.

    Execve: Agent/headless flags (listen/connect/reverse/tunnel) or
    remote-control binaries spawning shells. WRITE: Drop of
    binaries/scripts in ~/.local, /tmp, or /opt tool dirs.

    Execve: Commands altering firewall or enabling listeners
    (iptables, nft, ufw, firewall-cmd, systemctl start
    *ssh*/*telnet*, ip route add, tcpdump, tshark). Socket/bind:
    Process binds to a new local port shortly after knock.

    Detects command-line tools, agents, or scripts making outbound
    HTTPS connections to popular web services like Discord, Slack,
    Dropbox, or Graph API in an unusual context.

    Process executes itself or clones a child process that then
    connects to an external IP address and sends to and receives from
    a remote host. The implant binary executes, clones, connects,
    sends to, and receives from an external network address,
    establishing a backdoor channel.

    A process connects to a remote IP on port 80 or other common
    ports, then sends data to and receives data from the external
    host. Outbound socket connects followed by send and receive
    events to the same remote address indicate beaconing or
    reverse-shell communication.
